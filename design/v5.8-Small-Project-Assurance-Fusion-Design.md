# v5.8 小项目 Assurance Fusion 设计

## 目标

在不降低独立审查、设计覆盖和五维系统审计标准的前提下，消除 LEAF 小项目为 Critic、
Component Verifier、System Deep Audit 连续启动三个 fresh Worker 所产生的宿主基线重复。

## 适用条件

Core 仅在以下条件全部满足时请求 `assurance_bundle`：

- 当前为最后一个 Developer batch；
- VerificationLayers 为 LEAF，即只有一个设计组件；
- 架构 `file_list` 不超过 20 个审计文件；
- Critic 仍由独立于 Developer 的 fresh Worker 执行。

PLATE/FULL、多组件、超过 20 文件或任何 bundle 不完整时保持既有分层流程，不得猜测通过。

## Bundle 合同

Critic Worker 一次输出三个独立分区：

1. `verdict/findings/strengths/critic_feedback/assessment`：现有代码审查合同；
2. `component_verification`：component、coverage_map、missing/diverged、recheck_log；
3. `system_audit`：固定 architecture、code_quality、engineering、virtualization、
   team_design_coverage 五维，findings、P0/P1/P2、审计文件数和设计文档状态。

Core 不接受 Worker 自报计数作为授权事实：findings 重新计数，覆盖缺失重新检查，五维集合必须
精确相等。任一 P0/P1、MISSING/DIVERGED 或维度缺失都进入原有修复/回源路径；只有三分区全部
通过才一次性记录 Critic progress、组件完成、coverage/audit facts 和 convergence。

## 不变量

- Developer 与 Assurance Worker 上下文隔离；禁止 inline 自审。
- 五个审计维度保持不变；合并的是宿主调用，不是验收标准。
- 既有分层 Result 继续兼容；没有 bundle 时按 Critic → Component → System 路径执行。
- 大项目 fan-out 与 D39 不变；D13 不翻转。

## EARS 验收

1. While a final LEAF batch has at most 20 files, when Critic Action is built, the Core shall
   request a complete assurance bundle from one isolated Worker.
2. While a valid clean bundle is submitted, when Core recounts findings and coverage, the
   thread shall reach terminal without spawning Component Verifier or System Audit Workers.
3. While any bundle section is missing, malformed, blocking, missing coverage or lacks one
   audit dimension, when Core validates it, the thread shall fail closed or enter the matching
   existing repair path and shall never claim convergence.
4. While a project is PLATE/FULL or exceeds 20 files, when Critic approves, the Core shall keep
   the existing layered verification fan-out.
