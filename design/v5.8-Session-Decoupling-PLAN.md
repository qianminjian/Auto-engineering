# Auto-Engineering v5.8 会话解耦实施计划

> 状态：待实施｜批准日期：2026-07-29
> 设计：`design/v5.8-Session-Decoupling-Design.md`

## 1. 目标、顺序与约束

目标是先恢复真实运行验证可信度，再实现会话解耦、有界上下文和成本审计，最后通过
双宿主真实项目门禁。

实施顺序固定：

```text
Phase 64 可信度止血
→ Phase 65 会话解耦
→ Phase 66 上下文/产物/成本治理
→ Phase 67 双宿主真实验收
```

Phase 64 完成前，不再把无人值守中等规模真跑作为发布证据。每个功能或缺陷任务采用
TDD；串行执行 pytest；未经授权不提交、不推送、不发布。

## 3. Phase 65：确定性状态与宿主会话解耦

### T308：ExecutionSession 与事件契约

新增 Session 模型、事件、schema、Projector 和唯一 active session 不变量。

**EARS：** While thread 跨会话运行, when session 状态变化, the Event Store shall
原子记录转换，并从事件重建相同 session projection。

### T309：ResumeCapsule

新增 Capsule schema、builder、store、hash 校验和 ArtifactRef 列表。

**EARS：** While active Action 已持久化, when rollover 创建 Capsule, it shall
引用同一 Action 和 projection sequence，且不包含完整 transcript。

增加字段白名单、尺寸上限、缺失 Artifact、hash 损坏和 replay 测试。

### T310：ContextBudget 与 rollover 决策（历史实现，Phase 70 纠偏）

实现 BudgetPolicy、usage/estimate 输入、soft/hard limit 和确定性决策。

**EARS：** While budget 达到 hard limit, when Kernel 构建下一 Action,
the system shall 只返回 `session_rollover`。

阈值来自 FeatureManifest/HostProfile；Skill 和模板不得复制默认数字。

### T311：Rollover Action/Result 幂等恢复

扩展 Protocol Envelope discriminator、claim token、错误码和单 Tick 事务。

覆盖重复投递、重复 claim、竞争 claim、旧 session 晚到 Result、新 session 崩溃及恢复。

### T312：Claude/Codex 会话适配（异常恢复能力保留）

更新两个 Host Adapter、共享 Skill/Command 和规则模板：

- 旧会话停止执行工作 Action。
- 新会话只加载 ResumeCapsule。
- 提交 claim 后获取唯一 active Action。
- 不支持 rollover 的宿主 fail-closed。

两个宿主不得在 Core 中出现分叉业务逻辑。

### T313：Phase 65 验收

- 150+ Tick fixture 跨至少三个 session。
- rollover 各边界故障注入通过。
- 单会话基准与多会话 Core 事件/投影/verdict 语义等价。
- v5.7 旧线程兼容导入仅告警一次。

## 4. Phase 66：有界上下文、产物引用与成本审计

### T314：Stage Context Selector

扩展 StageContract，声明 required/optional fields、Artifact kind 和字节预算；Compiler
拒绝未声明历史和重复结构。

**EARS：** While Developer Action 被编译, when 历史有 100 个已完成批次,
the prompt shall 只包含 active batch、直接依赖、最新 feedback 和必要引用。

### T315：ArtifactRef 与精简 Worker Receipt

新增 Artifact schema/store、不可覆盖 hash、receipt 尺寸门禁及多 Agent/审计适配。

**EARS：** While Worker report 超过 inline 阈值, when 交付完成, the host shall
收到 ArtifactRef 与有界摘要，Core shall 仍验证独立 worker receipt。

### T316：逐 Tick Usage Ledger

扩展 Host SPI `collect_usage()` 和审计模型；未知值使用 null/unknown，不写零。

覆盖 Claude/Codex 原生 usage、估算回退、Worker、缓存字段、聚合和 PII 安全。

### T317：Checkpoint 与审计保留策略

拆分永久事实、可重建投影和临时产物；实现 dry-run 清理、引用完整性检查和恢复测试。
删除物理产物仍属于需单独授权的操作，本任务只实现机制和测试，不自动清理用户数据。

### T323：状态锚点与摘要隔离

为 BEACON、recap、`session_summary` 和 Capsule 增加来源与权威级别；Core 路由只读取
事件投影。覆盖 BEACON 过期、摘要重复、摘要与 Gate 矛盾、错误完成率和上下文压缩。

**EARS：** While 信息性摘要与投影矛盾, when 下一 Action 被构建, the Core shall
报告 drift、保持投影语义并拒绝用摘要改变 stage、batch、计数或 verdict。

### T324：修复循环与 Agent 预算

在 FeatureManifest/Policy 中建立 repair、Worker、Plate Audit、System Audit 和产物
尺寸上限；Host/Skill 只消费策略，不复制默认值。

**EARS：** While 任一循环或 Agent 计数达到 hard limit, when Kernel 选择下一动作,
the system shall 确定性 pause 或 rollover，并禁止 Architect 通过新增 batch 绕过。

### T318：Phase 66 成本与完整性验收

- Prompt 字节随 Tick 近似线性，不随完整历史二次增长。
- 每 session 不超过 hard limit。
- Usage 报表按 thread/session/stage/worker 聚合。
- 已报告 usage 的归因率不低于 95%，unknown 单独列示。
- 清理可重建副本后 status/resume/replay 仍通过。
- 过期 BEACON、重复/矛盾 recap 不改变 Core 投影和路由。
- Repair、Worker 和 Deep Audit 达策略上限后不再扩张。

## 6. 跨任务完成定义

每个任务完成必须同时具备：

1. 可复现 RED 证据。
2. 最小实现和 GREEN 证据。
3. 事件/schema/兼容边界测试。
4. 相关回归、Ruff 和 mypy。
5. Tracker 状态与验证数字更新。
6. 无密钥、临时调试、假通过或未解释 warning。

不得以“提示词更短”“运行未报错”或“宿主自动 recap”替代确定性验收。

## 7. Phase 70：自动上下文与成本治理纠偏

> 设计基线：`v5.8-Automatic-Context-Governance.md`。本阶段不新增用户命令，
> 不把固定 Tick、cache-read 或未知 usage 作为会话容量代理。

### T341：决策与负向契约

建立旧行为 RED：固定 8 Tick 触发 rollover、正常 compaction 改变 session、cache-read
触发换会话、用户看到人工交接。GREEN 后以上路径全部消失。

### T342：配置语义迁移

从 standard Profile 移除 `AE_SESSION_MAX_TICKS=8`；弃用 session tick/time 配置，
新增独立 `max_thread_ticks` 流程保险丝并提供兼容告警。

### T343：宿主自动 compaction 适配

Claude/Codex compaction 只产生观测事件，不产生业务 Result、不改变 session/stage/tick；
压缩后从 Event Store 与 active Action 无感继续。

### T344：ContextManifest 与块级去重

Action 编译记录 block id/hash/bytes/mode/authority，同一 hash 不得重复内联；顶层、
context、summary、spawn 间的同事实重复必须在模型调用前失败。

### T345：Stage 增量上下文与 Worker 隔离

按 Stage 落实最小字段；Coordinator 只接收 Worker 索引和 prompt ArtifactRef，各
Worker 按需读取自己的 prompt，主 Agent 只接收有界 receipt。

### T346：Prompt 与工具输出入口门禁

测试、lint、diff、搜索、Bash、MCP 和 Worker 输出先摘要/引用化；超限时返回最大
block 和 ArtifactRef，不得截断 active task、安全规则、验收条款或 Result schema。

### T347：Usage 语义与测量完整性

分离 input、cache read/write、output、Core payload、活动窗口；unknown 保持 null；
记录估算算法版本、重复 block bytes 和 Top 重复来源。

### T348：成本基准与回归 Harness

同 fixture/宿主/模型执行 before/after，报告累计值、每 Tick 增量、P50/P95/最大值、
stage/worker 归因；缺失 usage 时输出 `measurement_incomplete`，不判成本通过。

### T349：恢复协议收口

ResumeCapsule/claim 仅服务进程退出、compaction 失败后的恢复、手工恢复和跨宿主
接管；旧 rollover checkpoint 可读迁移，正常流程不要求人工新建会话。

### T350：真实长跑发布门禁

Claude Code 与 Codex 各运行至少 150 Tick 的返工/深审计轨迹，必须零人工交接、
零输入超限、零重复 block、状态等价；至少一个可控真实宿主观测 compaction，
不可观测宿主写 unknown；真实 usage 不完整则不得发布。
