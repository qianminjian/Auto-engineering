# v5.8 Gap Review 向导与真跑协议收敛设计

> 日期：2026-08-11｜更新：2026-08-12｜状态：已实现并通过自动验收｜来源：T432 真跑事故

## 1. 问题与边界

当前 Core 一次暴露全部 gap，要求宿主在聊天内逐项询问、最后批量提交。这使关键状态
落在不可审计、可被 clear/compaction 丢失的宿主内存中，也迫使用户一次理解多个跨层
问题。本设计把“当前项、累计决策、推荐依据”收回 Core；宿主只负责呈现当前 Action。

本阶段不让 Core 调用 LLM，不把聊天 transcript 变成状态源，不允许宿主替用户选择，
也不允许 Core 隐式修改测试项目的 Git 历史或工程依赖。

## 2. 决策

### 2.1 单项持久化，而非宿主本地批量

`gap_review` Action 每次只包含一个 `current_gap`：

```json
{
  "action": "gap_review",
  "mode": "wizard",
  "current_gap_index": 0,
  "total_gaps": 8,
  "current_gap": {},
  "decisions_so_far": [],
  "expected_format": {"decision": {}}
}
```

宿主提交单个 `decision`。Core 校验其 `gap_id` 必须等于当前项，以领域事件持久化后：

- `Fill/Defer`：进入下一未决 gap；全部完成后进入 Architect。
- `Research/Defer+Research`：进入 Research；研究结果绑定 `gap_id` 后回到同一 gap 复审。
- 非法或错位：返回稳定 Error，投影与当前游标不变。

旧 Action 若仍要求完整 `decisions`，只读兼容其活动消息；新 Action 不再生成批量模式。

### 2.2 Gap Analysis 契约

新 gap 除稳定标识与分级外必须包含：

- `evidence`：设计章节中的事实引用；
- `problem_statement`：可判断的问题陈述；
- `impact`：架构、实现、测试、安全或交付影响；
- `dependencies`：依赖 gap；
- `recommendation.resolution/reason/confidence`；
- `options[].resolution/meaning/enabled/disabled_reason`；
- `blocking_rule`。

Core 校验字段与枚举，不自行编造语义影响。旧 checkpoint 缺少增强字段时标记
`analysis_quality=legacy` 并给出“需重新扫描”错误，不输出虚构推荐。

### 2.3 推荐与审计

推荐来自 Gap Scan Worker，Core 只校验规则：architectural gap 的纯 `Defer` 必须禁用；
Research 必须声明查证目标；Fill 必须要求可写入设计的明确内容。决策事实保留
`assistant_recommendation`、`recommendation_accepted`、`decision_source=user` 和证据引用。

### 2.4 规划显示与路由标识

Architect batch 使用：

- `batch_title`：自然语言组织名称；
- `plate_keys`：从 Action `valid_plate_keys` 选择的稳定路由标识；
- `design_sections`：覆盖审计引用。

旧 `component` 仅作兼容输入；新 Action 的 expected format 和预校验不得再鼓励复用该字段。
执行游标以 `plate_keys[0]` 作为兼容主键，但完整 `plate_keys` 保留在计划和验证 Action 中；
组件验证合并读取所有关联 key 的设计声明，batch 不因多 key 重复执行。

### 2.5 新项目变更证据

`GitDiffExists` 接受 tracked diff、staged diff、已授权 commit，以及未跟踪但位于
`files_changed`/当前 task 范围内的真实文件。Core 不运行 `git add/commit`，也不因没有
Git 仓库而要求宿主擅自初始化；setup Action 明示 Git 是可选证据 Provider。

### 2.6 工程能力预检

ProjectProfile 只依据固定入口文件做确定性检查：声明 ESLint 9 且缺少
`eslint.config.*` 时要求 setup；Vitest 配置明确使用 jsdom 且 package 未声明直接依赖时
要求 setup。Core 不凭技术栈猜测依赖，也不自动写配置或安装包。

### 2.7 错误边界

CLI 将已知协议、投影与事件提交异常封装为 `ExecutionControl.ERROR` 的稳定 Action，并
恢复 EventStore 最近投影。未知内部异常仍 fail-closed、写 stderr 审计，不输出伪成功。

## 3. 状态与事件

- `pending_gap_decisions`：已验证的累计单项决策；不再只是当前 Result 临时字段。
- `gap_report_json.gaps[].resolution`：当前决策投影。
- 每次单项提交使用显式 Gap 状态事件；同 Stage 续作不产生伪 `StageAdvanced`。
- Action 的 `current_gap` 始终由持久化投影计算，不能由宿主传入游标。

## 4. EARS 验收

- While 存在多个未决 gap, when Core 构建 `gap_review`, the Action shall 只包含当前 gap、完整分析、推荐与合法选项。
- While 当前 gap 未决, when Result 指向其他 gap, the Core shall 返回稳定错误且保持同一 Action 语义。
- While 单项决定通过, when 下一 Action 构建, the Core shall 持久化累计决定并只推进到下一未决项。
- While Research 完成, when Core 回到 review, the Action shall 绑定原 gap 和研究证据并重新询问该项。
- While Critic 输出契约字段, when v1.1 Result 校验, the Core shall 从 Schema SSOT 接受并投影它们。
- While Critic MAJOR 触发返工, when EventStore 提交, replay projection shall 与 developer Action 状态一致。
- While 新项目只有未跟踪实现文件, when developer Guardrail 校验, the Core shall 认可范围内真实变更且不隐式 stage/commit。

## 5. 验证矩阵

单元：Gap 分析 schema、单项校验、推荐规则、路由标识、Git evidence。集成：多 gap
逐项恢复、Research 回流、Critic MAJOR EventStore、原生 v1.1 Result。验收：跨进程
resume、事件 replay、Claude/Codex archive smoke、真实产品长跑另行记录。
