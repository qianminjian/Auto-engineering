# v5.8 场景审计与运行韧性设计

> 更新：2026-08-29｜用途：把真跑会暴露的“跨边界”问题纳入整体设计，禁止继续按最终报错点状打补丁。

## 1. 总体结论

Auto-Engineering 的主矛盾不是单个 Stage 的字段，而是四个边界必须同时闭合：

1. Core 是唯一状态与路由事实源；Host 只能执行 Action，不得猜测身份、证明或下一步。
2. Action 是唯一副作用边界；同一 Action 的 Prompt、Worker、Result、Receipt 必须可关联、可恢复、不可混用。
3. 设计扫描、规划、开发、审查、修复、验证和终态必须以同一稳定设计身份贯通；advisory 发现不能自动改变 binding 设计。
4. 安装运行态必须来自独立制品；开发目录、宿主虚拟环境和长聊天上下文都不能成为隐式依赖。

因此，“测试全绿”只证明确定性内核；产品可用还必须有独立制品和真实宿主 L3/L4 证据。

## 2. 场景矩阵与不变量

| 场景 | Core 必须保证 | Host 必须保证 | 失败处置 |
|---|---|---|---|
| 新项目/设计文档 | 解析稳定 section 身份并逐项 Gap 覆盖 | 只提交业务分析语义 | 缺章节证据拒绝推进 |
| Gap Review/Research | 单项决策持久化；Research 仅 advisory | 不代用户批准 binding 变更 | WAIT_USER 或回 Architect |
| Architect/Developer | Plan、obligation、路由键来自同一 Candidate | Worker 使用 Core 给定 Prompt/权限 | Result 关联不符则 repair |
| Critic/深审计 | 仅 binding/objective P0/P1 触发 refine；advisory 记录但不阻断 | 独立 Worker 回执可核验 | 失败进入有界修复或 STAGNANT |
| Result 接收 | thread/action/correlation/tick 全绑定 | 不手工重写 Core-owned 字段 | `ACTION_NOT_ACTIVE` |
| 宿主启动/续作 | Lease 绑定 session 与 Build | 使用独立 runtime 和真实 session | 缺身份 fail-closed |
| Worker/机器异常 | 保留 active Action 与 Stop Report | OSError、超时、重试有界 | 稳定错误 + 可恢复诊断 |
| 重启/清理 | EventStore/checkpoint/handoff/runtime/blob 原子一致 | 不从聊天历史猜状态 | 显式 re-init 或 resume |
| 发布/安装 | 验收入口指向嵌套独立插件 | 清理 PYTHONPATH/VIRTUAL_ENV 等污染 | 非 hermetic 直接阻断 |
| done/TERMINAL | 只表示 Core 收敛，携带未验证产品边界 | L4 另行提交真实证据 | 未完成产品验收不得发布 |

## 3. 本次确定的协议修复

- Phase 0 不再接受只有 `stage` 的空结果；Gap Scan 保留领域层详细错误，Gap Review 兼容 `decision/decisions`，Research 允许带诊断的搜索失败。
- `design_change_requests` 在运行时验证来源、权威级别、影响章节和非空摘要，禁止结构化字段被二次序列化或缺省吞错。
- 系统深审计按 finding 的 `authority_class` 决定是否返工；计数与报告仍保留 advisory，但不把 advisory P1 伪装成阻断缺陷。
- Lease 缺少宿主 session 或 Build Identity 时拒绝创建；非连续 Action（错误、人工 Gate）不创建无意义 Lease。
- HostSupervisor 对 Action 总数和失败重试设置硬上限；超过上限返回稳定错误，不允许回调无限循环。
- `clear()` 作为显式 re-init 的原子操作，同时清理 checkpoint、protocol action、handoff、active project runtime 和 content-addressed blob。
- Codex Hook 和宿主子进程只使用 `.ae-runtime`；安装验收验证 `plugins/auto-engineering/bin/ae-run`，并清理开发环境注入的 Python 路径。

## 4. 尚未冒充完成的工作

以下工作不能仅靠单元测试宣称完成，必须作为下一轮产品门禁：

- T526/T411：真实宿主 input/cache/output/cost 统计与重复上下文阻断；JSON 字节预算不能替代供应商真实计量。
- 审计日志默认脱敏、摘要化和保留期策略；debug 全量日志必须显式开启。
- 150 Tick/长轨迹、文件副作用与 EventStore 同步故障注入、双宿主真实 L3/L4。
- 超长模块拆分和静态门禁基线 ratchet；本轮不通过放宽阈值掩盖架构债务。

## 5. 验收标准

- 自动门禁：全量 pytest、Ruff、mypy、metadata、规则同步、host package、静态门禁均通过。
- 结构门禁：Action/Result schema 与运行时 SSOT 无漂移；跨平台路径、缺 Lease、advisory P1、重试上限和清理完整性均有回归测试。
- 产品门禁：同一内容寻址 Build 在 Codex/Claude Code 中从空项目执行设计驱动命令，产生等价 `TERMINAL`；报告分别记录安装来源、Worker/Result 关联、恢复、成本和未验证项。
