# v5.8 方案 A：单协调者 Loop 收敛设计与实施计划

更新：2026-09-03
适用范围：`Auto-engineering` 当前实现、Host Adapter、Codex/Claude 宿主接入与公开 CLI。

## 1. 先说结论

当前 loop 容易中断，不是因为“等待时间不够”，而是因为系统同时存在多个事实源、多个协议入口和多个可能推进状态的角色：Python CLI、Orchestrator、旧 Supervisor 语义、Host Assembler、Worker 私有结果之间没有始终沿用同一个 Action 身份。

方案 A 的最终形态只有一条主链：

```text
主 Agent（唯一 Coordinator）
  └─ Host Driver：读 Action → 原样 spawn Worker → wait/observe → collect → finalize → 调一次 tick
       └─ Python Core：一次 tick 只做校验、事件提交、状态投影、生成一个下一 Action
            ├─ EventStore：新运行唯一事实源
            ├─ Artifact/Outcome Journal：Worker 结果与宿主事实的原子交接
            └─ StageHandlerRegistry：唯一 stage 路由
```

三条底线：

1. Python 不启动 LLM、Worker 或第二个协调循环；它是确定性 Tick Kernel，不是 Supervisor。
2. 主 Agent 拥有当前宿主会话和 Worker 生命周期；Worker 只交付业务产物，不得推进 Loop、spawn 其他 Worker 或填写宿主事实。
3. 所有恢复都围绕 `thread_id + action_message_id + execution_generation + fencing_token`，不凭自然语言、旧文件名或错误文本猜状态。

## 2. 对标原始设计与最佳实践

| 原始设计约束 | 当前应保留的实现 | 当前曾经的偏离 | 方案 A 修正 |
|---|---|---|---|
| D1/D17：主 Agent 驱动，Core 单 Tick | `dev-loop --init/--tick`、Execution Control | 旧 Supervisor 把 Python 变成长期协调者 | 删除 Supervisor；Host Driver 持续循环 |
| D9/D57：事件是事实，状态是投影 | SQLite EventStore、Reducer | checkpoint 与事件快照存在拼接风险 | 新运行只从 EventStore 恢复，checkpoint 仅显式导入 |
| D20：ActionCompiler 纯编译 | `ActionCompiler` 已有纯边界 | ActionBuilder 先写 proof/prompt，再编译 | 规划、编译、EffectExecutor 三段分离 |
| D53-D56：主 Agent 唯一 Coordinator、wait 不等于失败 | generation/fencing、resource_wait | 失败、超时、关闭、所有权不确定曾混为一类 | WAIT_RESOURCE、业务失败、OWNER_LOST 分流 |
| D58：canonical section 是稳定身份 | EngineeringModel、Assembler 校验 | Core 直到收到 Assembler 结果才发现错误 | Core 与 Assembler 共用纯章节校验器 |
| D27/D28：宿主事实和证据闭环 | Adapter、Collector、Finalizer、Journal | CLI/Worker 可重新拼机器事实 | invocation 模板是唯一输入，宿主只填原生事实 |

最佳实践只借鉴边界，不引入第二个运行时：Temporal 强调事件历史重放、Workflow 与 Activity 分工和 Activity 重试；AWS Step Functions 强调按错误类型有限重试与 Catch；Durable Task 强调持久化编排和长时间运行；LangGraph 强调 checkpoint、interrupt 和可恢复状态；Inngest/Hatchet 强调步骤幂等、失败可观测和 durable execution。方案 A 用现有 EventStore、Journal、generation/fencing 实现这些必要能力，不在当前项目再引入 Temporal 或其他外部引擎。

## 3. 分层和所有权

| 层 | 唯一职责 | 可以做什么 | 禁止做什么 |
|---|---|---|---|
| L0 Host Driver | 连续运行一条 Action 轨迹 | spawn、按 `worker_observation` bounded wait、观察、回收、调用公开 CLI | 改写 Action、推断 Worker 身份、创建第二个 loop |
| L1 Protocol | Action/Result/Worker 合同 | schema、identity、capability、error code | 业务路由、文件扫描降级、隐式兼容 |
| L2 Tick Kernel | 一次确定性状态转移 | validate、guardrail、handler、生成下一 Action | 调 LLM、spawn、等待、读宿主私有会话 |
| L3 Event Projection | 持久化和恢复 | append event、replay、projection、幂等 | 从两个来源拼状态 |
| L4 Evidence Plane | Worker 与宿主事实交接 | outcome、receipt、attestation、journal | 让 Worker 填宿主事实、用日志文本代替证明 |
| L5 Stage Handler | 每个 stage 的纯转移决策 | 根据 state/result 返回 TransitionDecision | 直接写文件、直接调用宿主、拥有另一张状态机 |

关键不变量：

- 同一 invocation 的 `worker_id/prompt_ref/outcome_path/receipt_path/generation/fencing` 必须来自同一个 Action，任何一项漂移都拒绝。
- `WAIT_RESOURCE` 只表示观察尚未完成，不改变 active Action；只有明确的 Worker 业务失败才进入失败处理。
- 等待策略由 Host Adapter 物化为 `host_execution.worker_observation`；每个 Worker 的
  `observation_path` 只保存当前 Action 最新的原生观察事实，并绑定 generation/fencing。
  观察写入不进入 EventStore、不推进 Tick；它只让宿主的 wait、owner 查询和“无法确认所有权”
  有可回放证据，不能成为 Python 第二循环。
- 迟到、重复和旧 generation 结果必须幂等或审计化，不能推进当前 projection。
- 修复 Coordinator 结果使用同一个 active Action 和已提交 Worker outcome，绝不重跑 Worker。
- 一个输入 Result 最多提交一次 `ResultAccepted` 与一个下一 `ActionIssued`；重放返回同一个下一 Action。

## 4. 当前实现对标结果

已经纠正：

- Python Supervisor、ephemeral backend、`--supervise` 入口已经从当前运行路径删除。
- 当前 Action 已只生成严格 `spawn.invocations[]`；Worker 编译器不再消费 `spawn.agents[]`，也不从 `subagent_prompt` 内联正文启动 Worker。
- Action schema 已要求 `contract_version + invocations`，旧字段不再是当前 Action 的合法字段。
- canonical section finding 已由 `auto_engineering/loop/section_findings.py` 统一校验，Core 和 Host Assembler 共用。
- CLI 状态查询通过只读隔离副本，不再直接摸 Orchestrator 私有状态；Orchestrator 不再实例化旧 StageRouter。
- EventStore 优先、状态冲突 fail-closed、generation/fencing、Host outcome journal 和 repair envelope 已有基础。
- ActionBuilder 已通过显式 `ActionPlan` 规划 payload、effect intents 和 preview receipts；EffectExecutor 只在 Tick 提交边界执行副作用。

当前残余与明确保留：

- 个别历史兼容文档仍需继续收口，但当前生产 CLI 与恢复入口已经统一为 EventStore-only；checkpoint 只通过显式 import/migration 进入新运行。
- 宿主运行时边界已进一步收口：Marketplace/Release 插件树保持只读，唯一可写的 Python/uv
  运行时为当前项目 `.ae-state/.ae-runtime`；`--project-root`、主 Runner 与生命周期 Hook
  共享同一解析入口，避免在只读插件缓存下于 `--init` 前中断。
- Runner 不再把依赖缓存错误绑定到项目运行时；默认复用 uv 公共缓存，验收通过显式
  `UV_CACHE_DIR` 使用受控缓存，避免首次启动因缓存未预热而被网络抖动中断。
- Runner 在项目 `.ae-state` 上使用有界 bootstrap 锁，并对缺失 `--project-root`、状态目录
  symlink 和死锁做 fail-closed/回收，避免并发 Hook 覆盖运行时或误写错误项目。
- 运行时 Feature 配置不再作为 Loop 启动前置；`FeatureManifest` 默认值直接生效，`ae.toml`
  只在存在时提供 `[project]` 能力事实和可选 Feature 覆盖，避免 ProjectProfile 与旧配置闸门
  互相阻断。显式 `doctor --init-config` 仍可生成标准治理配置。
- 历史候选 Build 的真实宿主失败与预算阻断只作为审计记录保留；当前 final140
  `5.8.0-rc.5+sha256.5892735d72dc9851` 已分别在全新 Codex 与 Claude Code 项目完成真实
  `TERMINAL/GOAL_ACHIEVED`，不得再把旧候选的待复验状态当作当前任务。
- 真实宿主在首个 `dev-loop --init` 前必须通过已安装插件根下 bundled `ae-run` 的
  `build-info --expect-build-id` 预检；身份不一致直接停止，不得切换旧缓存或手工修复。
- Worker 回写合同的 `argv_template` 已包含状态、句柄、模型、native result 和隔离证据的全部
  运行时占位符；失败 Worker 的缺失宿主事实使用显式 `unreported` 哨兵，completed 仍由 Core
  严格拒绝缺失句柄/隔离证据，避免真实宿主靠提示词猜命令。
- E2E 回归测试的直接 SQLite 连接已显式关闭；全量测试和覆盖率运行不再产生可避免的未关闭连接告警。
- 生产入口不再设置固定 `max_rounds`；固定 Tick/Round 仅可由显式历史兼容调用启用，不能成为
  宿主连续驱动的默认停止条件。
- 退役的 `StageRouter` 状态机已删除；原先仍被使用的字段清理函数已迁移到
  `loop/state_lifecycle.py`，当前生产路由只由 `loop.stages` Handler Registry 负责。
- 当前若干大文件超过项目行数建议，属于 P2 整洁债务，不得用拆文件改变协议语义来掩盖 P0 问题。

### A009：Prompt Artifact-only Action 收敛（已完成）

- 当前 Canonical Action 不再生成或接受 `subagent_prompt`；单 Worker 不再有该字段特例。
- 多 Worker 的 Coordinator 合并提示词写入内容寻址 Artifact，并由
  `coordinator_prompt_ref(path, sha256, size_bytes, media_type)` 引用。
- Worker 提示词只存在于 `spawn.invocations[].prompt_ref`，宿主实际启动只消费对应
  `host_execution.workers[i].native_launch_prompt`；Coordinator 不读取 Worker prompt 正文。
- 旧在途 Action 不能由普通运行路径降级；显式历史迁移边界必须拒绝或生成当前严格 Action。

验收：当前 Action Schema 拒绝 `subagent_prompt`；所有当前生产 Action 不含该字段；多 Worker
Coordinator ref 可独立按 SHA-256 校验，且 symlink 解析后不得逃逸项目根；公开 compact CLI 不重新
内联提示词；旧字段只能触发稳定迁移/拒绝错误。

## 5. 开发计划与顺序

### A001：严格 Worker 协议（已完成）

- 删除当前编译器 `spawn.agents` fallback。
- 要求 prompt 必须通过 `prompt_loader(prompt_ref)` 读取并校验 SHA-256。
- ActionBuilder、proof、Prompt logger、receipt 校验统一消费 `invocations`。
- Schema 删除 `agents`，当前 Action 缺少严格 invocation 直接拒绝。

验收：旧字段误入返回稳定错误码；当前 Action 不出现 `agents`；单/多 Worker 的 identity、hash、receipt、outcome 路径唯一。

### A002：Core 前置校验和修复（已完成）

- 提取纯 `normalize_section_findings`。
- Core 在任何状态推进前拒绝 unknown/duplicate/missing/invalid。
- Host Assembler 复用同一规则；拒绝结果投影为 `repair_current_action`，不重跑 Worker。

验收：复现 incident 的错误章节引用时，错误包含合法 canonical 引用；修复后使用同一个 `action_message_id`，旧 Result 不会再次消费。

### A003：Worker 交接合同（本批完成）

- 为每个 invocation 生成一套不可变交接记录。
- Collector 只接受当前 generation 和 active fencing；旧结果只写 stale audit。
- 把 native handle、actual model、isolation evidence 的来源限定为 Host API。
- 缺失输出与失败结果也携带当前 generation/fencing；Action 顶层绑定与宿主模板
  不一致时 fail-closed，避免恢复时把不同代的证据拼在一起。
- 统一 capacity、timeout、owner lost、business failure 的错误分类和重试上限。

验收：Host Assembler 的成功、失败、缺失输出、迟到结果路径均覆盖 generation/fencing
回归；本批专项目标测试通过。

### A004：Core/CLI 边界（已完成主要入口）

- Core 提供 `state_snapshot`、`active_action_snapshot`、`status_snapshot`。
- CLI 只负责文件边界、公开命令编排和宿主视图投影。
- 后续继续把恢复、终态记录和 metrics 读取收敛到公开 Core 查询/提交接口。

### A005：EventStore-only 新运行（已完成）

- init 创建 EventStore stream 和第一条 ActionIssued。
- tick/status/resume/finalize 只从同一 stream 恢复；不把 checkpoint 状态和事件 Action 拼在一起。
- checkpoint 只保留显式 `legacy_import`，导入后立即生成新事件，不再作为正常运行事实源。
- 已增加公开 `--import-checkpoint <id>` 迁移入口；普通 CLI 的 tick/status/resume
  已移除 checkpoint fallback，兼容读取只保留在显式迁移和内部 legacy façade。
- 恢复 API 已完成语义隔离：生产 `restore()`/`restore_from_event_store()` 必须显式使用
  EventStore；历史 checkpoint 仅通过命名的 `restore_from_checkpoint()` 兼容入口访问，
  不再由一个未命名参数分支同时承担两种运行语义。
- 已移除 EventStore 运行中对 checkpoint-only replay 的隐式回退；两套存储若出现不一致，
  只能按冲突或显式迁移处理，不能悄悄拼接事实。
- 增加空流、损坏流、projection mismatch、重复提交、跨进程恢复回归。
- 本批新增恢复源隔离、checkpoint-only replay、公开 repair/迟到 Result/重复 Result 幂等、跨进程 resume、宿主资源等待与有限重试、双宿主 Adapter 等价和只读插件树项目运行时 bootstrap 回归；全量串行验证 `2706 passed, 1 skipped`，
  覆盖率 `90%`。
- 最新追加公开 CLI 容量耗尽等待、有限 Worker 重试耗尽、真实 Runner 跨进程 resume、多 Worker 部分完成交接和单组件跨进程 TERMINAL E2E 后，全量串行回归为
  `2706 passed, 1 skipped`。

### A006：纯 Action 规划和副作用执行（已完成）

- `ActionBuildContext` 只包含不可变快照。
- `ActionBuilder.build_plan()` 统一返回显式 `ActionPlan(payload, effect_intents, preview_receipts)`；不得写文件、调用 UUID 或读取 clock。
- `ActionCompiler` 只注入 identity/runtime revision/issued_at 并校验 schema。
- Event transaction 的提交边界由 `EffectExecutor` 执行 intent 并登记实际 receipt；部分执行失败会清理本批已执行的命名 artifact，未提交 intent 不进入下一 projection。
- `ActionBuilder.build_action()` 仅保留无副作用的 payload 读取兼容包装；任何绕过 `ActionPlan` 的 effect 执行均稳定失败 `ACTION_PLAN_REQUIRED`。已补齐纯规划、稳定引用和 EventStore 提交落盘回归。

### A007：公开 CLI 端到端矩阵（已完成；真实宿主在 A008）

至少覆盖以下轨迹，每条都经过公开命令或真实宿主接口，不只调用内部类：

当前已落地公开 CLI 的 `init → finalize → validate → tick` 单 Action 轨迹、单组件跨进程到 `TERMINAL` 的黄金轨迹、
Worker timeout/capacity exhaustion → `WAIT_RESOURCE` 失败轨迹与有限重试耗尽、checkpoint-only 运行拒绝回归、
公开 CLI 异步 Worker 继续执行轨迹、“错误提交 → 同一 Action repair →
validate → tick”闭环、“重复 Result → 同一下一 Action 幂等重放”轨迹，以及
“迟到 Result → stale audit、当前 Action 不变”轨迹；

T676 补齐 Project Setup 的失败交接：宿主单个 Action 最多一次就地修复，之后以
`project_setup_failed` Result 把失败交回 Core；Core 以 EventStore 计数并在三次连续失败后
返回 `WAIT_RESOURCE`，不再依赖宿主进程内的隐式循环。
Codex/Claude Adapter 的 Core 语义等价回归已补齐；真实双宿主轨迹属于 A008，不能用本矩阵替代。

T688 补齐 Architect 结果拒绝边界：`ARCHITECT_PLAN_INVALID` 只返回当前 Action 的
`repair_current_action`，不再通过 guardrail retry 生成新的 Architect Action。若共享 outcomes
已包含全部 completed Worker Attestation，宿主视图必须改为
`worker_outcomes_committed`、`spawn_permitted=false`，Coordinator 只修复 payload 后重新
Finalize/Validate/Submit；EventStore 不新增该拒绝 Result 的 `ResultAccepted` 或新的 Worker
执行身份。

1. `init → spawn → async wait → record-worker-outcome → finalize → validate → tick`。
2. 多 Worker 并行、部分完成、容量耗尽后有限重试。
3. wait 到期但 Worker 仍运行：输出 `WAIT_RESOURCE`，不失败、不重复 spawn。
4. OWNER_LOST、宿主关闭、迟到结果、重复结果、旧 generation 结果。
5. 非法 canonical section：返回 repair；修复后继续同一 Action。
6. 跨进程/跨 session resume；最终 `TERMINAL`，无人工手动续接。
7. Codex 与 Claude 在 Action/Result/Event 语义上等价，只替换 Host Adapter。
8. `init → spawn → bounded wait → record-worker-observation → owner uncertain`：观察记录
   与 Action/generation/fencing 绑定，Core active Action、EventStore 和业务预算保持不变，
   不得把 wait 到期或 owner 不确定伪造成 Worker 失败。

## 6. EARS 验收标准

- While 当前 Action 存在，when Host Driver 观察到 wait 超时，the Core shall 保持同一 active Action 并返回 `WAIT_RESOURCE`，不得把超时改写成 Worker 失败。
- While 当前 Action 是严格 spawn Action，when 任一 invocation 缺少 `prompt_ref`、hash、outcome 或 receipt 绑定，the system shall 在 spawn 前返回稳定协议错误。
- While Worker 已提交合法业务 outcome，when Coordinator Result 被拒绝，the system shall 生成 `repair_current_action`，不得再次启动该 Worker。
- While Result 的 section finding 使用未知、重复或缺失的 canonical identity，when Core 尚未提交 ResultAccepted，the Core shall 列出全部违规并保持 projection 不变。
- While 两个来源的 Action identity 不一致，when 任一 CLI 恢复入口读取状态，the system shall 返回 `STATE_SOURCE_CONFLICT`，不得拼接快照继续运行。
- While Result 已被接受，when 同一 Result 再次提交，the Core shall 返回完全相同的下一 Action，且事件流不新增第二次推进。
- While loop 已到合法终态，when Host Driver 结束进程，the system shall 能通过 EventStore/status 证明 `TERMINAL`，不得要求用户手工输入 continue/supervise。

## 7. 测试与发布门禁

测试分层：

- 单元：协议 schema、identity、reducer、handler、纯校验器，目标覆盖核心模块 90%。
- 集成：EventStore + Core + Assembler + Journal，覆盖事务、幂等、恢复和 fencing。
- 公开 CLI E2E：覆盖上述 A007 七类轨迹；关键路径必须至少一条 Codex 和一条 Claude。
