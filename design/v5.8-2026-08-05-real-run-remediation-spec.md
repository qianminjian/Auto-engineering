# v5.8.0-rc.5 真跑纠偏 Spec（2026-08-05）

## 1. 决策摘要

本 Spec 以原始 Loop 设计和当前已验证代码为双重基线，纠正 rc.4 针对
`voice_clone_for_auto_CC_Design` 真跑报告所做的点状修复。问题不在 Voice Clone 业务，
而在 Loop 工程把宿主交互粒度误写成 Core 状态粒度，随后又用未版本化字段修补状态机。

保留两项有效修复：设计文档相对路径按 project root 恢复、统一 status 优先读取
EventStore。撤销单 Gap 单 Tick、`finding_ref` 私有门禁和 `.ae-contracts-required` 标记。

## 2. 原设计不变量

| ID | 不变量 | 实现锚点 |
|---|---|---|
| I1 | Core 只做确定性状态、协议、验证与审计，不调用 LLM | `TickOrchestrator` / Host Skill |
| I2 | 一个 Action 对应一个可原子验证的 Result | `action.schema.json` / `stage-result.schema.json` |
| I3 | Gap Review 一次覆盖当前全部未决 gap；宿主内部逐项询问 | `ActionBuilder` / `_validate_gap_review_decisions` |
| I4 | Research 按队列逐 Tick；队列清空前不得进入 Architect | `GapReviewHandler` / `ResearchHandler` |
| I5 | 公共协议向后兼容只能扩展已声明字段，不可私自增加顶层字段 | v1.1 schema fail-closed |
| I6 | Gate 只依据真实项目事实，不从 spawn 行为推断业务契约 | ProjectProfile / EngineState.contracts |

## 3. 故障链与纠偏

| 编号 | rc.4 故障 | 违背的不变量 | rc.5 纠偏 |
|---|---|---|---|

## 4. 协议 Spec

### 4.1 Gap Review Action

```json
{
  "action": "gap_review",
  "gaps": [{"id": "gap-1"}, {"id": "gap-2"}],
  "expected_format": {
    "decisions": "必须无重复地完整覆盖 action.gaps"
  }
}
```

宿主必须按数组顺序逐项询问用户，在本地累积决策；未完成全部询问前不提交 Result。
Core 不保存交互游标，不产生 `current_gap`、`gap_index`、`remaining_count` 或
`interaction_mode`。

### 4.2 Gap Review Result

```json
{
  "stage": "gap_review",
  "decisions": [
    {"gap_id": "gap-1", "resolution": "fill", "fill_content": "..."},
    {"gap_id": "gap-2", "resolution": "research"}
  ]
}
```

- `actual gap_id set == pending gap_id set`：接受并原子推进。
- 缺失：`GAP_REVIEW_DECISIONS_INCOMPLETE`，状态保持 gap_review。
- 重复或未知：`GAP_REVIEW_DECISIONS_INVALID_SET`，状态保持 gap_review。
- `research` 与首次 `defer_research` 进入有序队列；每个研究 Result 只消费队首。
- 已研究的 `defer_research` 在复审时归一为 defer，保证终止。

### 4.3 Action Schema Gate

所有经过 envelope、policy snapshot、loop/context budget 扩展后的最终 Action，必须在
EventStore/checkpoint 持久化和 stdout 输出前通过 `action.schema.json` Draft 2020-12 校验。
未知字段或类型漂移抛出 `INVALID_ENVELOPE`，不得写入 active Action。

## 5. Gate 与状态 Spec

- `ProfileCommandGate`：timeout 显示阈值；not-found/OSError/负退出码显示完整 command 与
  有界错误文本；正常非零退出码显示 stdout/stderr 尾部。
- `AuditGate`：P0/P1 使用阈值；P2 默认 `warn-only`，配置显式非负阈值时才参与失败判定。
- `ContractGate`：`contracts` 非空执行四项静态检查；空字典或未注入返回
  `not_applicable=true`；不得读取 ad-hoc marker。
- `ae status --format json`：EventStore-first，仍精确返回 `thread_id`、`round`、`stage`、
  `verdict`、`majors_in_a_row`、`total_majors`、`recent_history`。
- PLAN_REFINE：继续使用已有 `refine_request_json`、`scope_component`、`scope_plate`、
  `design_ref` 与 PlanPatch；不增加未进入 schema/prompt 的 `finding_ref`。

## 6. EARS 验收

- While Gap Review 有 N 个未决 gap, when Core 构建 Action, the system shall 暴露全部 N 个 gap。
- While 宿主只提交部分、重复或未知 gap decision, when Core 校验 Result, the system shall 返回稳定错误且不推进 stage。
- While 多个 decision 请求 Research, when 每个 Research Result 到达, the system shall 按队列逐项消费并仅在队列清空后进入 Architect 或复审。
- While Core 生成任意最终 Action, when 持久化或输出前, the system shall 通过 v1.1 schema，否则 fail-closed。
- While ProjectProfile 命令无法启动, when Gate 返回 verdict, the message shall 包含实际 command 和结构化原因，不得仅显示空 `exit=-1`。
- While Audit 仅发现任意数量 P2 且未显式配置 P2 阈值, when Gate 判定, the verdict shall 不因 P2 阻断。
- While EngineState.contracts 为空或未注入, when ContractGate 运行, the verdict shall 为 N/A；非空时 shall 执行契约检查。
- While EventStore 存在 active projection, when `ae status --format json` 执行, the CLI shall 返回该投影且保持精确 7 字段。

## 7. 验证与发布边界

代码级准入：专项回归、全量 pytest、Ruff、mypy、规则同步检查和元数据一致性全部通过。
产品级准入：使用新版本制品在 Claude Code/Codex 对同一多 gap fixture 重跑，确认宿主逐项询问、
Core 一次接收完整 decisions、多个 Research 不提前跳 Architect。未取得真实宿主证据前，状态只能是
“代码修复完成、待产品验收”，不得宣称正式发布可用。
