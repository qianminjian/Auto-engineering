# v5.8 Action-Scoped Host Context Spec（T530，待批准）

## 1. 决策请求

请求把 D13 的“固定 Tick 不换宿主模型上下文”改为：Core ExecutionSession 继续稳定，用户仍只
启动一次；产品层 Supervisor 为每个 Action 创建一次性 host context，完成后销毁，不携带旧
transcript。普通宿主 compaction 仍不改变 Core 状态，ResumeCapsule 仍只用于进程/宿主异常接管。

该变更不是让用户手工 continue，也不是按 Tick 猜测状态；Action identity 是唯一切分边界。

## 2. 为什么必须翻转

同一 frozen Canary 的受控证据：

| Build | 机制 | Worker | 外层 input/cache | 结论 |
|---|---|---:|---:|---|
| 818e7459 | 完整 Action stdout | 4 | 5.01M/4.85M | 失败 |
| 41f2b07e | compact Action | 4 | 3.29M/3.05M | 失败 |
| d51c7397 | 533-byte launcher | 4 | 4.72M/4.59M | 失败 |
| ad1c63a0 | Assurance 4→2 | 2 | 3.79M/3.57M | 失败 |

非翻转路径已消除正文、工具参数和重复验收 Worker；剩余量随同一聊天历史的 LLM/tool 回合累计，
CLI 指令无法删除宿主已经持有的 transcript。继续删字段或换便宜模型不能改变 O(n²) 重放形态。

## 3. 方案比较

### A. Action-scoped Supervisor（推荐）

确定性 Supervisor 持有 Core thread/action lease，不持有业务对话。每轮把 compact envelope、
内容寻址 Coordinator/Worker refs 和本 Action 权限交给全新 host context；执行器只完成一个
Action，写 Action-scoped work files 后退出。Supervisor validate/finalize/tick，再启动下一轮。

优点：从机制上消除历史重放；Core、EventStore、Finalizer 和现有恢复事实不变；用户一次启动。
代价：需要 HostInvocation SPI、进程/原生 Agent 能力探测、流式日志转发和取消/预算管理。

### B. 保持长会话并继续压缩

优点：实现最少。缺点：四轮 L3 已证明只产生边际和随机波动，不能达到 token 目标；不推荐。

## 4. HostInvocation SPI

```text
HostSupervisor
  acquire active Action from Core
  compile ActionExecutionRequest artifact
  HostInvocationBackend.execute(request) -> ActionExecutionReceipt
  validate/finalize/tick
  repeat until WAIT_USER/WAIT_RESOURCE/TERMINAL/ERROR

HostInvocationBackend
  probe() -> supported | unsupported(reason)
  execute(request_ref, timeout, budget) -> process/session identity + receipt_ref
  cancel(identity) -> bounded graceful cancellation
```

`ActionExecutionRequest` 只含 schema、thread/action/tick/stage/build identity、project root、
compact envelope ref/hash、Coordinator ref/hash、Worker launchers、work files 和允许的工具策略。
不得包含旧 Action、旧工具输出、自由文本 recap、完整 EventStore 或聊天 transcript。

`ActionExecutionReceipt` 只含 action identity、host context identity、status、work-file digests、
usage 和稳定错误码。业务 Result 仍由既有 Finalizer 从 Core Canonical Action 生成。

## 5. 宿主后端

### Codex

使用本机受支持的 `codex exec --ephemeral -C <project> --json --output-schema <schema>`；
显式加载已安装内容寻址 Release，不访问开发目录。每个 invocation 使用新 ephemeral session，
stdout 写有界日志文件，由 Supervisor 解析，不回灌下一 Action。

### Claude Code

使用官方 print mode：`claude -p --no-session-persistence --output-format stream-json`，配合
`--max-turns`、`--max-budget-usd` 和权限策略。只有 capability probe 明确允许当前调用位置创建
子进程/新上下文时启用；不得删除 `CLAUDECODE` 等保护变量绕过嵌套限制。若插件内不支持，返回
`HOST_ACTION_CONTEXT_UNAVAILABLE`，而不是偷偷退回长会话。

后续若宿主暴露原生 session factory，新增 backend 即可；Core 不变。

## 6. 权限、恢复与审计

- Supervisor 是产品层确定性进程，不调用 LLM、不修改业务文件。
- 每个 host context 只能提交当前 action work files；陈旧路径由 T519 重绑，journal 由 T527 恢复。
- context 崩溃时按 T517/T518 写 worker/action failure；同一 Action 有界重试，不推进 Tick。
- WAIT_USER 由外层用户会话展示；选择写 Result 后 Supervisor 继续。外层会话不执行业务 Action。
- 每次启动/退出记录 host context id、backend、build、action id、usage、exit status；不记录 Prompt 正文。
- cancel 先正常终止；超时升级仍遵守 5/10/15 分钟和禁止无限重试。

## 7. 迁移

1. 增加 `HostContextStrategy=continuous|action_scoped`，旧 Build/read path 兼容 continuous。
2. Product Skill 默认请求 action_scoped；probe 失败时 fail-closed，不自动降级。
3. 先在 Codex frozen Canary 验证，再验证 Claude；双宿主均通过才改变发布默认值。
4. active continuous thread 只在 Action 边界迁移；在途 Action 保持旧 runtime revision，避免漂移。
5. 回滚只切回已发布 continuous Build，不改写事件或 journal。

## 8. EARS 验收

1. While one user launch drives multiple Actions, when an Action reaches execution, the
   Supervisor shall create a fresh host context containing no prior transcript.
2. While a fresh context completes, when it writes a receipt, the Core shall bind it to the
   exact active Action and deterministically produce the same next Action as continuous mode.
3. While a backend is unavailable or nested invocation is unsupported, when probe runs, the
   product shall return `HOST_ACTION_CONTEXT_UNAVAILABLE` and shall not degrade to long context.
4. While a context crashes after Worker journal preparation, when Supervisor retries, the Core
   shall restore authoritative outcomes and shall not respawn completed Workers.
5. While frozen Canary runs, when terminal usage is measured, Codex outer input shall be at most
   1.0M and cache read at most 1.5M; Claude shall reach terminal within USD 2.00. These are the
   proposed T530 approval budgets and become binding only with this decision approval.
6. While either host misses terminal, budget, provenance or dev-directory isolation, when the
   release gate evaluates, L4 and publication shall remain blocked.
