# v5.8 标准 Marketplace 安装设计

> 日期：2026-08-29｜状态：已批准｜适用范围：插件安装、卸载、升级和本机验收

## 1. 目标

Auto-Engineering 的安装行为必须与普通 Codex/Claude Code 插件一致：由宿主原生
Marketplace 管理注册、下载、缓存、启用、版本和卸载。Auto-Engineering 不建立第二套
安装器、运行时缓存或用户可见的 staging 管理体系。

安装脚本的职责只有两项：调用宿主 CLI 完成“卸载旧版本 → 注册 GitHub Marketplace →
安装插件”，以及把宿主命令错误原样转换为可诊断的失败。运行时只使用宿主已安装缓存，
不访问本项目开发工作区。

## 2. 唯一安装来源

默认来源为 `qianminjian/Auto-engineering`。Codex 可以用 `--ref` 固定分支或标签；Claude
Code 使用仓库默认分支，因为当前 Claude CLI 没有等价的 `--ref` 参数。安装入口：

```bash
uv run python scripts/install_codex_local.py --source qianminjian/Auto-engineering
uv run python scripts/install_claude_local.py --source qianminjian/Auto-engineering
```

等价的宿主原生命令：

```bash
codex plugin marketplace add qianminjian/Auto-engineering
codex plugin add auto-engineering@auto-engineering

claude plugin marketplace add qianminjian/Auto-engineering --scope user
claude plugin install auto-engineering@auto-engineering --scope user
```

## 3. 幂等重装顺序

每次显式重装按以下固定顺序执行：

1. 卸载用户级 `auto-engineering@auto-engineering`；不存在时视为幂等成功。
2. 删除用户级同名 Marketplace；不存在时视为幂等成功。
3. 从 GitHub 注册同名 Marketplace；失败立即终止。
4. 通过 Marketplace 安装插件；失败立即终止。
5. 由宿主 `plugin list`/`marketplace list` 验证启用状态和来源。

脚本不得直接删除宿主缓存、修改宿主配置文件或猜测缓存路径。卸载、缓存清理和权限
修复均交给宿主 CLI，避免因权限位、版本布局或平台差异造成二次故障。

## 4. 开发目录隔离

安装脚本可以从开发目录执行，但开发目录只能作为脚本所在位置，不能作为 Marketplace
来源。任何本地路径来源仅用于测试夹具或 archive smoke，不得出现在用户安装文档和发布
验收命令中。真实安装验收必须检查宿主报告的 Marketplace/插件来源不在开发目录内。

## 5. 与 archive smoke 的边界

`build_release.py`、`stage_release()` 和 `--stage-only` 仅用于离线打包、归档和安全测试，
不属于产品安装路径。archive smoke 通过不能证明 Marketplace 安装或真实宿主 L3/L4；两类
证据必须分开记录。

## 6. 验收标准（EARS）

- While 用户级旧插件或 Marketplace 不存在, when 执行任一标准安装脚本, the script shall
  继续完成 GitHub Marketplace 注册和插件安装。
- While 用户级旧插件存在, when 执行重装, the host shall 先卸载旧插件再安装同名新版本，
  且不直接操作宿主缓存。
- While 标准安装完成, when 宿主列出 Marketplace 和插件, the reported source shall 不属于
  开发工作区，插件状态 shall 为 enabled。
- While GitHub 来源、宿主 CLI 或插件安装失败, when 安装脚本退出, the script shall 返回非零
  状态并保留可执行命令和宿主错误，不伪造安装成功。
