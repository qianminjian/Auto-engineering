# v5.8 Compact Host Control Plane 设计

## 问题

Core Action 同时承担持久化事实、调试展示和宿主执行输入，导致完整 Prompt 与上下文在
同一聊天历史中按 Tick 反复放大。治理内核应保留完整事实，但产品控制面不应复制正文。

## 双视图协议

### Canonical Action

- 由 Core 生成并提交 EventStore；Action v1.1 语义不变。
- Finalizer、Result 校验、恢复、审计始终读取 Canonical Action。
- 不因节省 token 删除 `instruction/context/expected_format` 等权威字段。

### Compact Host Envelope

当产品 Skill/Command 设置 `AE_HOST_ACTION_VIEW=compact` 时，CLI stdout 只返回：

- Action/Thread/Tick/Stage/Causation identity；
- `execution_control` 与 runtime/build identity；
- `host_execution.work_files/recovery/workers`；
- 精简 `spawn` invocation（只含 worker identity、effort、isolation、prompt ref/hash）；
- `coordinator_prompt_ref` 与 SHA-256；
- Gate、current gap、终态 verdict 和稳定错误等必须直接展示的有界字段。

`instruction`、`context`、`subagent_prompt`、tasks、coverage map 等大字段不进入 stdout。
Coordinator prompt 由 Core 写入 `.ae-state/effects/prompt/`，路径必须相对项目根、内容摘要
匹配、只读消费。未知 shell 或未设置 compact 时继续输出完整 Action，保持兼容。

## 宿主执行

1. 每次只保留最新 compact envelope。
2. inline Action 读取一次 `coordinator_prompt_ref`；spawn Action 只把 invocation 的
   `prompt_ref` 交给对应 fresh Worker。
3. Worker 完成后只写 native outcome；Coordinator 依据当前 work files finalize。
4. 下一 Tick 不打印上一 Action、完整 diff、完整 Result 或完整 Prompt。

## 安全与恢复

- Prompt ref 使用既有项目根边界检查和 SHA 校验；不得接受绝对路径或 `..`。
- Canonical Action 不从 compact envelope 反向重建，避免宿主篡改事实。
- committed/native-ready recovery 继续由 `_prepare_action_for_host` 投影，compact 只压缩展示。
- Gate/ERROR/TERMINAL 不得因压缩丢失用户决策、错误码或终态。

## EARS 验收

1. While 产品宿主启用 compact view, when CLI 输出任一 Action, the CLI shall omit all
   inline prompt bodies and expose digest-bound prompt refs plus execution identity.
2. While Finalizer validates a compact-driven Result, when it loads the active Action, the Core
   shall use the unchanged Canonical Action and produce the same deterministic transition.
3. While a pre-developer thread resumes, when future roots never existed, the compact envelope
   shall return the active Architect rather than a reconciliation Gate.
4. While L3 runs on both hosts, when cost evidence is collected, the release gate shall fail if
   either host misses terminal state or exceeds the approved input/cache budget.
