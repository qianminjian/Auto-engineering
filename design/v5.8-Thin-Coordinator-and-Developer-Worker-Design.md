# v5.8 Thin Coordinator 与 Developer Worker 设计

> 状态：T530-T531 已实施，T532 验收中｜任务：T530-T533｜日期：2026-08-22

## 1. 结论

保留 BEACON D13：一次用户启动、固定宿主协调会话、宿主自动 compaction，Capsule 仅用于
异常恢复。先落实业界通用的“持久状态 + 薄协调器 + 隔离 Worker + 有界回执”，不得把
Action-scoped 新会话当作尚未验证的默认解法。

当前 Architect、Critic、Verifier 与 Deep Audit 已使用 fresh Worker，但 Developer 仍由主
Agent inline 执行。代码阅读、编辑、测试和返工因此进入长期 Coordinator transcript；此前
“非翻转优化已耗尽”的结论不成立。

## 2. 目标架构

```text
User starts once
  -> Thin Coordinator: compact Action / spawn / wait / finalize / tick
       -> Architect Worker
       -> Developer Worker (one active batch)
       -> Critic / Assurance Worker
       -> Verifier / Deep Audit Worker
  -> Core EventStore / Projection / Canonical Action remain authoritative
```

Coordinator 不读取设计正文、业务源码、完整 diff、完整测试日志或 Worker Prompt；不直接修改
业务文件。所有需要业务推理和工具执行的 Stage 使用 `fresh_context` Worker。Worker 只完成
当前 Action，不驱动 Loop、不派生 Worker，并把完整正文写入内容寻址 Artifact。

## 3. Developer Worker 合同

- `developer` 从 `INLINE` 改为 `SINGLE_WORKER`，默认一个 `high` Worker。
- 输入仅含 active batch、tasks、直接依赖、最新 finding、ProjectProfile 摘要、设计与证据引用。
- Worker 在目标项目根执行 TDD、编辑和验证；Git mutation 仍由用户授权控制。
- 输出仍使用既有 Developer 业务字段；receipt、attestation、proof 和协议 identity 由
  HostExecutionAssembler 独占生成。
- Developer 失败、超时、恢复和 prepared journal 复用既有 T517-T519/T522/T527 语义。

## 4. 有界返回与成本边界

原生 Worker outcome 的 `summary`、业务 payload 和工具输出在进入 Coordinator 前必须通过
字节门禁。完整 diff、测试日志和报告只能以 ArtifactRef 交付；同一 hash 不重复写入 Action。
Coordinator 每个 Tick 只保留最新 compact envelope、句柄状态、Result 摘要和稳定错误。

独立 Worker 会重复加载必要的宿主基线，因此优化目标不是“总成本为零”，而是阻止业务正文和
长工具轨迹污染主会话，并按 Coordinator/Worker/Stage 分开归因。

## 5. T530-T533 决策顺序

1. T530：Developer Worker 化，主 Agent 禁止 inline developer。
2. T531：Worker outcome/Coordinator 输入有界化，补齐真实宿主防回灌测试。
3. T532：同一 Build 执行 Claude/Codex frozen Canary，记录主会话与 Worker 分项用量。
4. T533：仅当 T532 仍未满足批准的成本门禁，才重新评审 Action-scoped Supervisor；不得自动
   翻转 D13，也不得用换模型、删审计或降低验证标准代替根因修复。

## 6. EARS 验收

1. While Developer Action is active, when Core builds host execution, the system shall emit
   exactly one fresh Developer Worker invocation and shall not authorize inline execution.
2. While a Developer Worker executes, when it reads or edits project files, the Coordinator
   shall receive only bounded outcome fields and ArtifactRefs, not file bodies or full logs.
3. While any business Worker completes, when Finalizer produces Result, the Core shall bind the
   same Canonical Action, receipt, attestation and journal semantics used by existing spawn stages.
4. While one user launch drives the Loop, when Actions advance, the Coordinator shall only
   dispatch, wait, finalize and tick; it shall not perform business-stage reasoning or edits.
5. While T532 evaluates the frozen Canary, when cost evidence is incomplete or over budget, the
   release shall remain blocked and T533 shall return to explicit architecture review.

## 7. T532 首轮真实证据

Claude Code；两宿主安装验收均确认产品入口不访问开发目录。Codex frozen Canary 的首个宿主

薄协调器和 Developer Worker 路径在真实宿主生效。Critic 发现设计偏差后，Core 正确回到
Developer 修复 Action；15 分钟边界中止后，`developer/round 4` checkpoint 仍可由新会话恢复。

第二宿主会话在执行恢复前因 Codex WebSocket 与 HTTPS 连接连续失败而终止，未形成 terminal

## 8. T532 恢复链路统一不变量

同一 Codex checkpoint 的后续复验暴露三类相互关联的协议缺口，必须作为 Host/Core 边界问题
统一修复，禁止继续以宿主手工改 Result 或重建线程规避：

1. **完成事实与修复事实分离**：`BatchCompleted` 只允许把未完成 batch 计数一次；Critic 要求
   返工时发出 `WorkReopened`，Developer 完成返工时发出 `WorkRepairCompleted`。后者只修复
   cursor，不增加 progress，并将 cursor 投影到第一个未完成 batch 或组件末尾。
2. **游标由领域事件独占**：连续多轮 Critic MAJOR 不得重复把 cursor 从 B2 回退到 B1；恢复时
   即使旧 checkpoint 已有漂移，`WorkRepairCompleted` 也必须依据 completed batch IDs 自愈，
   不通过 Stage handler 或 post-progress 隐式改状态。
3. **先验证、后准备 journal**：Assembler 必须先规范化、绑定和验证 Worker attestation，再写
   prepared journal、receipt 或 proof。验证失败不得留下“已准备”假事实；历史错误 journal 只可
   append-only 归档到 rejected outcomes，再基于原生 outcome 重新验证。
4. **原生证据只做确定性白名单规范化**：宿主工具返回的 `{"fork_context": false}` 与
   `fork_context=false`、`{"fork_turns": "none"}` 与 `fork_turns=none`，以及两项同时存在且
   值完全一致的对象视为同一语义，由 Assembler 在任何 journal 写入前统一规范化；其他对象、
   `true`、冲突值或未知键继续 fail-closed。

新增 EARS 验收：While a completed batch is under repair, when repeated MAJOR/recovery events occur,
the Core shall preserve completed progress exactly once and heal the cursor through explicit domain
events. While native isolation evidence uses a whitelisted equivalent representation, when the Host
finalizes an outcome, the Assembler shall canonicalize it before attestation validation; invalid
evidence shall create no prepared journal.

## 9. T534 启动 Root Lease

宿主调用 Skill 时必须先把启动 `cwd` 的真实绝对路径固定为 `invocation_project_root`，首个
`--init` 及其所有失败处理都只能使用该根。相对 `--design-doc` 必须在该根内解析；文件不存在、
越界或首个 Core 调用失败时，宿主只报告稳定错误并停止，禁止搜索父目录、`/tmp`、其他项目、
插件缓存或同名设计文档，禁止改写 `--project-root` 后重试。Core 返回首个 Action 后，只允许
验证 `action.project_root == invocation_project_root`，不相等即 `HOST_PROJECT_ROOT_DRIFT`。

While a Loop invocation is bound to its startup project root, when design input is missing or an
init command fails, the Host shall fail closed without discovering or initializing another project;
relative and absolute design paths outside the bound root shall be rejected by Core.

## 10. T535 Architect Batch ID 闭包

PLAN_REFINE Action 必须携带 Core 计算的 `batch_id_policy`：完整 `reserved_batch_ids`、
`next_numeric_id` 与“新 batch 从该序号连续分配且不得复用”的规则。该字段同时进入 Canonical
Action、Worker Prompt 和 expected format，不由 Coordinator 从历史状态猜测。Architect 返回
冲突 ID 时 Core 继续使用同源 baseline 集合 fail-closed；旧 checkpoint 保留兼容的非连续 ID，
Result repair 只能复用已完成 outcome 并按该 policy 修正，
不得重新 spawn。绝对文件路径不影响 batch 身份；身份由已激活 baseline 的稳定 ID 集合决定。

While PLAN_REFINE adds batches, when Architect compiles a patch, the Worker shall receive the full
reserved ID set and deterministic next numeric ID, and shall allocate only fresh IDs without relying
on chat history or repository discovery; legacy nonnumeric IDs shall retain duplicate-only validation.

## 11. T532 Codex 终态与 T536 机器操作

Build `5.8.0-rc.5+sha256.7f9fc5ac2a667bda` 从原 checkpoint 续跑到 Tick 18
`TERMINAL/GOAL_ACHIEVED`：固定正确根、未 init、未重复 spawn，15/15 测试及最终 Critic 通过。
但宿主仍曾手工抄错一次 Prompt ref 和一次 Finalizer 输入路径，分别产生无效文件探测与
`HOST_OUTCOME_INPUT_INVALID`。Core 的拒绝是正确的，根治方式不是继续加强自然语言，而是由
Core 在 `host_execution.operations` 中生成 action-scoped `finalize/validate/submit` argv；宿主
只允许逐项原样执行，不再拼接 runner、work file 或 project root。

本次两个终态前续跑会话分别消耗约 2,439,722 input（2,330,880 cached）和 1,350,270 input
（1,280,256 cached），T532 成本门禁明确失败。该事实允许提交 T533 架构评审，但 D13 翻转仍
必须取得用户显式批准；T536 属于现有 Host 合同的确定性收敛，可先实施。
