# v5.8 Action-Scoped Host Context Spec（T533，已批准）

> T530-T532 完成后，同 Build Codex 已到终态但成本门禁仍失败。用户于 2026-08-23 批准
> 方案 B：修订 D13，保持工程线程连续，宿主模型上下文按 Action 隔离并由 Supervisor 自动续作。

## 1. 条件性决策请求

请求把 D13 的“固定 Tick 不换宿主模型上下文”改为：Core ExecutionSession 继续稳定，用户仍只
启动一次；产品层 Supervisor 为每个 Action 创建一次性 host context，完成后销毁，不携带旧
transcript。普通宿主 compaction 仍不改变 Core 状态，ResumeCapsule 仍只用于进程/宿主异常接管。

该变更不是让用户手工 continue，也不是按 Tick 猜测状态；Action identity 是唯一切分边界。

## 3. 方案比较

### A. Action-scoped Supervisor（推荐）

确定性 Supervisor 持有 Core thread/action lease，不持有业务对话。每轮把 compact envelope、
内容寻址 Coordinator/Worker refs 和本 Action 权限交给全新 host context；执行器只完成一个
Action，写 Action-scoped work files 后退出。Supervisor validate/finalize/tick，再启动下一轮。

优点：从机制上消除历史重放；Core、EventStore、Finalizer 和现有恢复事实不变；用户一次启动。
代价：需要 HostInvocation SPI、进程/原生 Agent 能力探测、流式日志转发和取消/预算管理。

### B. 保持长会话并继续压缩

优点：实现最少。缺点：四轮 L3 已证明只产生边际和随机波动，不能达到 token 目标；不推荐。

## 4. HostInvocation SPI

```text
HostSupervisor
  acquire active Action from Core
  compile ActionExecutionRequest artifact
  HostInvocationBackend.execute(request) -> ActionExecutionReceipt
  validate/finalize/tick
  repeat until WAIT_USER/WAIT_RESOURCE/TERMINAL/ERROR

HostInvocationBackend
  probe() -> supported | unsupported(reason)
  execute(request_ref, timeout, budget) -> process/session identity + receipt_ref
  cancel(identity) -> bounded graceful cancellation
```

`ActionExecutionRequest` 只含 schema、thread/action/tick/stage/build identity、project root、
compact envelope ref/hash、Coordinator ref/hash、Worker launchers、work files 和允许的工具策略。
不得包含旧 Action、旧工具输出、自由文本 recap、完整 EventStore 或聊天 transcript。

`ActionExecutionReceipt` 只含 action identity、host context identity、status、work-file digests、
usage 和稳定错误码。业务 Result 仍由既有 Finalizer 从 Core Canonical Action 生成。

Canonical Action 同时下发 `result_contract`：它是从 Stage Result 类型事实源生成的机器合同，
与面向模型展示的 `expected_format` 分离。Backend 在成功回执前校验 Coordinator payload；若数组或
对象只是被合法 JSON 二次序列化为字符串，只允许解码一次并原子改写。其余类型错误以
`HOST_ACTION_OUTPUT_INVALID` 进入宿主失败路径。Finalizer 在任何 proof/journal 写入前重复执行同一
校验并运行 Stage 语义校验，禁止把错误推迟到后续 Tick。

## 5. 宿主后端

### Codex

使用本机受支持的 `codex exec --ephemeral --ignore-user-config -C <project> --json
--output-schema <schema>`；保留认证但隔离用户插件/MCP/个性化配置，项目规则和原生
multi-agent 仍由 Codex Runtime 提供。若当前 CLI 不支持该开关，capability probe 必须失败。
显式加载已安装内容寻址 Release，不访问开发目录。每个 invocation 使用新 ephemeral session，
stdout 写有界日志文件，由 Supervisor 解析，不回灌下一 Action。

### Claude Code

使用官方 print mode：`claude -p --no-session-persistence --output-format stream-json`，配合
`--max-budget-usd`、进程超时和权限策略。只有 capability probe 明确允许当前调用位置创建
子进程/新上下文时启用；不得删除 `CLAUDECODE` 等保护变量绕过嵌套限制。若插件内不支持，返回
`HOST_ACTION_CONTEXT_UNAVAILABLE`，而不是偷偷退回长会话。

外层 Action context 使用 `--setting-sources project --strict-mcp-config --mcp-config
'{"mcpServers":{}}'`、
`--disable-slash-commands --no-chrome --effort low` 隔离无关 user/local 配置、MCP 与 UI 能力；保留
项目配置和 CLAUDE.md。不得使用会同时禁用项目规则或 OAuth/keychain 的 `--safe-mode/--bare`。

后续若宿主暴露原生 session factory，新增 backend 即可；Core 不变。

Capability probe 不得只检查可执行文件存在；必须从当前 CLI help 验证本 Build 使用的全部隔离、
非持久化、结构化输出和预算参数。任一缺失时在模型调用前返回稳定 capability error，禁止把旧版
CLI 参数错误延迟到真实 Action。

## 6. 权限、恢复与审计

- Supervisor 是产品层确定性进程，不调用 LLM、不修改业务文件。
- 每个 host context 只能提交当前 action work files；陈旧路径由 T519 重绑，journal 由 T527 恢复。
- context 崩溃时按 T517/T518 写 worker/action failure；同一 Action 有界重试，不推进 Tick。
- WAIT_USER 由外层用户会话展示；选择写 Result 后 Supervisor 继续。外层会话不执行业务 Action。
- 每次启动/退出记录 host context id、backend、build、action id、usage、exit status；不记录 Prompt 正文。
- Supervisor 在每次 WAIT/ERROR/HANDOFF/TERMINAL 返回或宿主操作抛出稳定协议异常时，
  从 Action、Execution Control 和 Receipt 确定性生成有界停止报告；报告只含当前 Action、
  最近回执、稳定原因码和下一步，不由模型自由总结，不改写 Core active Action。
- 原生 Worker API 不报告模型标识时，`actual_model` 使用稳定事实值 `unreported`，不得猜测；
  `isolation_evidence` 必须复制 Host Adapter 物化的调用参数事实，不得复制抽象 `fresh_context` 策略。
- cancel 先正常终止；超时升级仍遵守 5/10/15 分钟和禁止无限重试。
- Claude 的 USD 2.00 是整个 Supervisor/thread 验收预算，不是单 Action 预算；每次调用只获得
  Receipt journal 扣除历史实际成本后的剩余额度，跨进程恢复不得重置，耗尽时不得再调用模型。
- Claude CLI 的预算检查允许一次推理单元超调；Backend 必须先从剩余额度扣除安全预留，再把
  可调用额度传给 CLI。失败 Result 的顶层零 usage 不得覆盖 `modelUsage` 中的真实 token/cost。

### 6.1 Core 拒绝后的同 Action repair

Result 被 Core 拒绝不等于 Worker 事实失效。Outcome journal 的 `rejected` 与
`assembly_rejected` 状态仍可能包含已经完成的、绑定到同一 `action_message_id` 的 Worker outcomes；
恢复投影必须先按 identity 校验并按 journal 原文原子写回 outcomes，再生成 Coordinator-only repair 包。
该 repair 包必须显式声明 `spawn_permitted=false`、`required_operation=repair_coordinator_then_finalize`，
并只提供 `outcomes_ref`/`result_ref` 等引用，禁止重新暴露 Worker 启动合同。

Finalizer 处理上述 journal 时以 journal outcomes 和 `outcomes_fingerprint` 为唯一事实源：宿主可以修复
Coordinator payload，但不能替换 worker id、native handle、attestation、完成时间或 outcomes 顺序。
身份、fingerprint 或 outcomes 失配是不可协调的 `OUTCOME_JOURNAL_CONFLICT`，Supervisor 必须在当前
Action 边界立即生成稳定 ERROR/Stop Report，不得创建下一 context、重试 Worker 或静默退出。

EARS：While a Core-rejected Result has an authoritative outcome journal, when the same Action is
repaired, the Host shall restore and reuse the journal outcomes without spawning Workers again.
While outcome identity or fingerprint conflicts, when Supervisor handles it, the system shall project
ERROR with a deterministic Stop Report and shall not advance the active Action.

## 7. 迁移

1. 增加 `HostContextStrategy=continuous|action_scoped`，旧 Build/read path 兼容 continuous。
2. Product Skill 默认请求 action_scoped；probe 失败时 fail-closed，不自动降级。
3. 先在 Codex frozen Canary 验证，再验证 Claude；双宿主均通过才改变发布默认值。
4. active continuous thread 只在 Action 边界迁移；在途 Action 保持旧 runtime revision，避免漂移。
5. 回滚只切回已发布 continuous Build，不改写事件或 journal。

## 8. EARS 验收

1. While one user launch drives multiple Actions, when an Action reaches execution, the
   Supervisor shall create a fresh host context containing no prior transcript.
2. While a fresh context completes, when it writes a receipt, the Core shall bind it to the
   exact active Action and deterministically produce the same next Action as continuous mode.
3. While a backend is unavailable or nested invocation is unsupported, when probe runs, the
   product shall return `HOST_ACTION_CONTEXT_UNAVAILABLE` and shall not degrade to long context.
4. While a context crashes after Worker journal preparation, when Supervisor retries, the Core
   shall restore authoritative outcomes and shall not respawn completed Workers.
5. While Core rejects a Result after Worker completion, when the same Action enters repair, the Host
   shall expose Coordinator-only recovery with `spawn_permitted=false` and preserve the journal fingerprint.
6. While the repaired Result conflicts with authoritative Worker outcomes, when Supervisor receives it,
   the system shall produce stable `OUTCOME_JOURNAL_CONFLICT` ERROR/Stop Report and no next context.
7. While frozen Canary runs, when terminal usage is measured, Codex outer input shall be at most
   1.0M and cache read at most 1.5M; Claude shall reach terminal within USD 2.00. These are the
   proposed T530 approval budgets and become binding only with this decision approval.
8. While either host misses terminal, budget, provenance or dev-directory isolation, when the
   release gate evaluates, L4 and publication shall remain blocked.
9. While product evidence is evaluated, when it only claims completion without numeric usage,
   unique per-Action context receipts, terminal facts and resolved runtime-source isolation, the
   release gate shall reject it rather than treating declarative fields as proof.
10. While a Coordinator payload contains a JSON-stringified array or object, when the backend exits,
   the product shall decode it exactly once, validate it against `result_contract`, and submit a native
   JSON value; unrecoverable payloads shall fail before any committed outcome journal is written.
11. While a supervise run yields or terminates, when control returns to the outer host, the product
   shall persist a deterministic stop report without conversation history or business payload bodies.

## 9. T543 Codex 受控真跑事实

- Structured Output 要求每个 properties 字段均在 `required` 中；Codex 专用输出 schema 以
  nullable `error_code` 兼容成功语义，通用跨宿主 schema 不变。
- 首次生成 standard profile 后必须在同一进程刷新 RuntimeConfig，并以显式 project root 覆盖 cwd。
- Finalizer 对 legacy Coordinator 的同值 `stage` 回显做兼容剥离，任何异值仍以
  `COORDINATOR_IDENTITY_OVERRIDE` 拒绝；新 Prompt 不再要求 Core-owned identity。
- Action Receipt 已持久化 context/build/action/tick/stage/usage/digest；不持久化 Prompt、环境或 transcript。
- `--ignore-user-config` 的两 Action 探针由约 765k input 降到约 408k，约下降 47%。正式 frozen
  Canary 自动完成 Gap、Architect、两批 Developer 与 repair；25 项业务测试和全部工程门禁通过。
- 五个成功 Action 加 Critic 启动尝试累计约 994,227 input、817,920 cache read、9,790 output；
  Critic 在执行业务前遇到 Codex 账户硬额度。因未达 terminal，不能把“低于 1.0M”判为成本通过。
- 宿主错误必须归一化为 timeout、resource_exhausted、execution_failed。额度耗尽返回
  `WAIT_RESOURCE`，保留同一 active Action；不得误报 Loop 失败，也不得消耗业务重试预算。
- 最新内容寻址 Release archive 已通过 package、隔离安装、doctor、minimal tick、status/resume、
  runtime identity 与 design authority；真实产品安装、Codex terminal 和 Claude terminal 仍阻断 T544。
- T544 产品证据必须由同一 artifact 绑定 build、逐 Action Receipt、唯一 context、terminal event、
  数值 usage 和真实 runtime source；旧版仅含 pass/discovered/complete 声明的证据不得通过发布门禁。
- Supervisor 仅在真实 `done` 后，从 Receipt journal、EventStore 和已安装 `build-info.json` 原子生成
  artifact；源码身份、非终态、复用 context、缺少 terminal event 或人工声明均不能生成发布证据。
- Claude frozen Canary 首轮证明其会输出带身份的 `result` 包装；Core 现仅在固定键集合、全部身份
  同值且 status 成功时解包，任一漂移继续拒绝。第二轮自动完成 Gap 与 Architect 后进入 Developer。
- 第二轮实际成本为 Gap USD 0.661090、Architect USD 1.325861；CLI 在剩余 USD 0.013049 时仍先
  产生 USD 0.177335 才报 exhausted，累计 USD 2.164286。新 Backend 预留 USD 0.20 推理超调，
  并以 `modelUsage` 修正失败 Result 的零 token；该运行未达 terminal，Claude 成本门禁判失败。
- Cancellable Runner 每 5 分钟输出纯时长心跳，15 分钟沿用有界超时；不转发 Prompt、工具参数
  或 transcript。相对 `--design-doc` 现按显式 `--project-root` 解析，跨目录产品调用不再误拒绝。
- 双宿主 probe 现从 CLI help 校验本 Build 的公开参数；Claude 2.1.220 未公开的 `--max-turns`
  已移除。无效 MCP 配置使用稳定 `HOST_CLAUDE_LAUNCH_CONFIG_INVALID`，不再归为模型失败。
- 本机无模型验证确认完整隔离组合返回 `No MCP servers configured`；单用 strict MCP 仍会加载用户
  插件，因此隔离合同必须保持完整参数组合，不得删减成单一 flag。
- T545 根据 2026-08-24 真跑补齐 `result_contract`、Backend/Finalizer 双层强类型边界、一次性
  JSON 二次序列化恢复和确定性 Stop Report；Critic 实现缺陷继续自动回 Developer，计划/契约缺口
  继续按既有 PlanPatch 回 Architect，不新增人工确认点。
- `additionalProperties=false` 是可执行约束，inline/spawn 两条 Finalizer 路径都必须拒绝合同外字段；
  `expected_format` 新增字段时必须同步声明机器类型，否则 Action 构建立即 fail-closed。
- 可选业务字段以“缺省”表示未提供；若显式出现就必须满足 Stage JSON 类型，不允许用 `null`
  绕过 Backend 后再在 Core Schema 失败。旧 Schema 为读取历史数据保留的宽类型不反向放宽新宿主写入。
