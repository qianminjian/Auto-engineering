## 二、实际使用路径分析

### 唯一真实执行路径

```
用户: /ae:dev-loop "需求"
  → commands/dev-loop.md driving loop
  → ae dev-loop --init (Python 引擎)
  → while action != done:
      gate? → --tick (无 result)
      spawn? → spawn subagent → 收集输出 → --tick --result
      developer? → inline TDD → --tick --result
  → GOAL_ACHIEVED
```

**这个路径使用的模块**：TickOrchestrator, StageRouter, BatchState, EngineState, GuardrailChain (G1-G6), Gates (safety/audit/build), 3 个核心 prompt (architect/developer/critic)

**这个路径不使用的模块**：StandaloneDriver, Provider 抽象, Metrics/自进化, PII 四层, OTLP, Context Offloading, 5 层验证的 4 层, G7-G12 guardrail, CLI 子命令 (agent/checkpoint/progress/gate-check --all)

### 为什么这些模块被创建但未使用

| 模块 | 设计意图 | 为什么未使用 |
|------|---------|------------|
| StandaloneDriver (1213行) | 脱离 Claude Code 独立跑, bank 内网 | Ollama 内网部署从未验证, 无真实使用场景 |
| Provider 抽象 (620行) | 多 LLM 平台 | Anthropic 之外从未真实调用 |
| Metrics/自进化 (2250行) | AI Coding 度量, 阈值学习, 棘轮控制 | AE_METRICS=1 需手动开启, 数据累积需 ≥30 需求 |
| PII 四层 (412行) | 银行 PII 合规 | Agent 模式下 LLM API 链路不可拦截, 仅警告 |
| OTLP (184行) | 分布式追踪 | 无 collector 部署, 每 tick 3 次重试日志噪音 |
| Context Offloading (490行) | Stage 间上下文传递 | design_spec 为空, 摘要质量低, T152 未修复 |
| 5 层验证(后4层) | 多维度质量审查 | 实际只有 critic 执行了真实审查 |
| G7-G12 Guardrail | TDD/Regression/新鲜度/AuditTiming | 默认关闭或从未触发 |
| CLI checkpoint/agent/progress | 调试/手动操作 | 非主路径, Skill 驱动不需要 |

## 三、简化方案

### 删除项（物理删除代码和测试）

#### 3.1 StandaloneDriver + Provider 抽象（~2000 行）

**删除**：`loop/standalone_driver.py`, `providers/` 下所有非 Anthropic provider, `cli/dev_loop.py` 中 `--standalone` 路径

**理由**：
- Bank 内网 Ollama 场景从未验证, 设计阶段过早
- Provider 抽象 5 个实现, 只有 Anthropic 真实使用
- `--standalone` CLI flag 增加理解复杂度
- 真跑 T55 确认: Agent 模式下 Ollama 不适用

**保留**：`providers/base.py` (LLMProvider Protocol — 仅类型定义), AnthropicProvider

#### 3.2 Metrics/自进化体系（~2250 行）

**删除**：`metrics/` 下全部模块 (collector, signals, diagnoser, ratchet, threshold_learner, enrichment, suggestions, rule_discoverer, transcript_parser, _paths)

**理由**：
- AE_METRICS=1 默认关闭, 所有功能位于条件分支
- 阈值学习需要 ≥30 需求数据, 从未在生产中达到
- 信号检测/诊断/棘轮/规则发现全链路从未端到端验证
- 20 个 AE_ 环境变量中 6 个与 metrics 相关

**保留**：无。如需度量, 从 git history + vitest 输出直接统计更简单。

#### 3.3 Context Offloading + Summarization（~490 行）

**删除**：`context/` 下全部模块

**理由**：
- offload 摘要质量极低 (19-32 chars), T152 未修复
- design_spec 为空 (T150), offloading 失去输入
- Agent 模式用 Claude Code 的 context 管理, 不需要引擎侧 offloading

#### 3.4 OTLP Tracing（~100 行）

**删除**：`observability/tracing.py`

**理由**：无 collector 部署, 每 tick 3 次重试 ERROR 日志噪音。保留 audit_log.py (LLM 调用日志有价值)。

#### 3.5 PII 系统简化（~300 行）

**删除**：`pii/guardrail.py` (G10 PIIGuardrail), `pii/redactor.py` 中 Agent 模式不可达的路径

**保留**：`pii/rules.py` (5 类 PII 规则定义), `pii/redactor.py` 中 Standalone 可用的扫描函数

**理由**：Agent 模式下 LLM API 链路在 Claude Code 进程内, auto-engineering 无法拦截。保留规则定义供未来使用。

#### 3.6 Guardrail 精简：G1-G6 保留, G7-G12 删除

**删除**：
- G7 REDGuardrail: AE_STRICT_RED 默认关闭, 从未触发
- G8 FreshGuardrail: Gate 快照新鲜度, 非核心
- G9 RegressionGuardrail: revert-red-restore, 从未在真实项目触发
- G10 PIIGuardrail: 同 3.5
- G11 FileAccessGuardrail: batch 文件白名单应在引擎层强制, 不在 guardrail
- G12 AuditTimingGuardrail: 证据组合检测器, 从未触发真实拦截

**保留**：G1 RequirementValid, G2 PlanExists, G3 GitDiffExists, G4 TestsPass, G5 GitClean, G6 NoDeferredBlockingGap

**理由**：G1-G6 覆盖了基本质量门禁（需求存在/计划存在/有变更/测试绿/已提交/无阻塞缺口）。

#### 3.7 验证层精简：5 层 → 2 层

**删除**：component_verifier, plate_deep_audit, system_verifier, system_deep_audit 对应的 prompt 文件和 stage handler

**保留**：critic（diff 级代码审查）

**理由**：
- component_verifier: design_spec 为空 (T150), 从未产出有效审查
- plate_deep_audit: 3-agent 并行 spawn 从未端到端验证 (T165)
- system_verifier/system_deep_audit: PLATE 模式自动跳过, 单 plate 项目永远触发不到
- 5 层验证的理论基础（频率×范围矩阵）正确, 但实现上无法提供足够的 subagent 输入

**替代方案**：critic 的审查范围扩展到"设计→代码对齐"（当前只做 diff 审查）。

#### 3.8 CLI 精简：5 子命令 → 2 子命令

**删除**：`ae agent`, `ae checkpoint`, `ae progress`, `ae gate-check --all`

**保留**：`ae dev-loop` (主命令), `ae doctor` (环境诊断), `ae --status` (查看进度)

**理由**：
- `ae agent`: 单次 Agent 调用, Skill 驱动不需要
- `ae checkpoint`: checkpoint 管理内部使用, 无需独立 CLI
- `ae progress`: 进度查看合并到 `--status --verbose`
- `ae gate-check --all`: 全量 gate 在 dev-loop 内自动运行

#### 3.9 Commands/ 精简：11 → 3

**删除**：`project-agent.md`, `project-ci.md`, `project-tdd.md`, `project-worktree.md`, `checkpoint.md`

**保留**：`dev-loop.md`, `code-review.md`, `audit.md` + `progress.md`（合并到 status）

**理由**：删除的 command 从未被 Skill 引用, 是模板/说明文件。

#### 3.10 Feature Flag 精简：20 → 8

**删除 feature flag**：
- AE_METRICS, AE_TOKEN_TRACKING (跟随 metrics 删除)
- AE_OTLP_ENDPOINT (跟随 OTLP 删除)
- AE_CACHE_CONTROL (prompt caching — 仅 Anthropic API, 实际未被 Engine 使用)
- AE_LLM_PROVIDER, AE_MODEL_ROLE, AE_PROVIDER_ROLE (跟随 Provider 精简)
- AE_PII_GUARDRAIL, AE_PII_GUARDRAIL_MODE (跟随 G10 删除)
- AE_PII_INBOUND, AE_PII_OUTBOUND (跟随 PII 简化)
- AE_STRICT_RED (跟随 G7 删除)
- AE_PRODUCTION, AE_MAX_TOOL_CALLS, AE_GATE_TIMEOUT (合并到默认行为)

**保留**：
- AE_DEBUG (DebugTracer — 生产诊断有价值)
- AE_AUDIT_LOG (LLM 调用日志)
- AE_AUDIT_LOG_DIR (日志路径)
- AE_PII_ENABLED (PII 规则定义保留)
- AE_LOG_LEVEL
