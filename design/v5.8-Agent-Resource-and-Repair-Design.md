# v5.8 Agent 资源与 Repair 契约设计

> 日期：2026-08-12｜状态：已实施｜任务：T433

## 1. 方案比较

### A. 仅修改宿主提示词

宿主遇到线程上限时回收完成 Agent 并重试。改动小，但旧宿主或错误实现仍会向 Core 提交
`spawned=false`，只能得到通用 `SPAWN_REQUIRED`，恢复信息不足。

### B. 宿主生命周期 + Core 可恢复分类（采用）

宿主负责资源回收和有限重试；Core 识别标准化 `spawn_error_code=HOST_AGENT_CAPACITY`，保持
active Action 不变并返回同 Stage 可恢复 Action。未知 spawn 失败仍 fail-closed。

## 2. 协议决策

1. Result 可在 `spawned=false` 时提交 `spawn_error_code`；线程/并发槽耗尽统一映射为
   `HOST_AGENT_CAPACITY`，原始脱敏诊断保留在 `spawn_error`。
2. Core 返回 `action=resource_wait`、`resource=agent_slot`、`retry_stage` 和恢复建议；
   Execution Control 使用 `WAIT_RESOURCE`，不要求用户做业务决策，也不推进 Tick。
3. 宿主收到资源等待后回收已完成 Worker，等待容量变化，再重新执行原 active Action；
   不用失败 Result 递归调用 `--tick`。
4. Repair Result 的 `plan_patch.base_revision` 改为可选。缺失时 Core 注入 active revision；
   显式值与 active revision 不同仍返回 `PLAN_REVISION_CONFLICT`。
5. Architect Action 提供 `repair_contract`：`active_revision`、`inherited_obligations`、
   `valid_plate_keys`、`batch_template`、`task_template`。Prompt 不再要求回显已知 revision。

## 3. EARS 验收

- While spawn 因宿主 Agent 容量不足失败, when Result 提交标准错误码, the Core shall 保持
  active Action/Stage/Tick 并返回 `WAIT_RESOURCE`。
- While 资源恢复, when 宿主重试原 Action, the Core shall 接受真实 Worker receipt 并继续。
- While repair Result 未提供 base revision, when Core 构建 candidate, it shall 注入 active
  revision；显式过期 revision 仍 fail-closed。
- While Architect 生成 repair plan, when Action 编译, it shall 获得完整结构模板和继承事实，
  不需要从聊天历史推断。
