# v5.8 状态冲突协调与任务续作实施计划

> 执行约束：按 TDD 逐项实施；每项先补失败测试，再写最小实现，最后运行定向回归。

**目标：** 用户显式提交设计文档时，Core 在恢复旧 Action 前核验当前项目；一致则自动续作，冲突则只允许用户选择“重新初始化”或“修复状态并继续”。

**架构：** 在 CLI 启动选择与 `TickOrchestrator.restore()` 之间增加只读的 InvocationIntent/Compatibility 层。冲突复用现有 Gate 与 `WAIT_USER`；选择通过领域事件进入 recoverable reinitialize 或独立 `PLAN_RECONCILE`，不复用 `PLAN_REFINE`，不删除审计数据。验证层按 task kind 约束证据，静态 ContractGate 不再充当可执行测试。

**技术栈：** Python 3.12、Click、SQLite EventStore/CheckpointStore、JSON Schema、pytest。

## 全局停止条件

- 同类失败达到两次时停止参数式重试，回查设计假设。
- 需要物理删除 `.ae-state`、改写旧事件或 Agent 代选时立即停止，视为设计违背。
- dirty worktree 中用户无关改动与目标文件重叠时暂停，不覆盖、不回滚。
- 未取得全量与产品安装验收证据前，不生成或发布下一 RC。
